# 📋 Итоговый план разработки прототипа
**Жанр:** Top-Down, Room-by-Room, Combat, Local MP Ready  
**Ядро:** MonoGame + .NET 8 | **Многопоточность:** Архитектурная с 1 дня, активная с 2 этапа  

---

## 🏗 Базовые принципы архитектуры
| Поток                               | Ответственность                                                                             | Пакеты                        | Синхронизация                                              |
| ----------------------------------- | ------------------------------------------------------------------------------------------- | ----------------------------- | ---------------------------------------------------------- |
| **🟦 Main (Render/UI/Input)**       | `Update`/`Draw`, `SpriteBatch`, `Myra`, `MonoSkelly`, `Extended.*`, камера, чтение очередей | Только чтение готовых данных  | `Channel<T>.Reader.TryRead()` в начале `Update()`          |
| **🟨 Logic (AI/Combat/State)**      | `Stateless`, боевая логика, спавн, управление комнатами, детерминированный рандом           | `Stateless`, `ObjectPool`, DI | Фиксированный шаг 1/60. Пишет в `Channel<LogicResult>`     |
| **🟪 Physics (Collision/Dynamics)** | `Aether.Physics2D.Step()`, коллизии, отбрасывание, гравитация                               | `Aether.Physics2D`            | Отдельный поток. Результаты позиций → `Channel<Transform>` |
| **🟫 Data (IO/Logging)**            | Сохранение, загрузка, структурированные логи                                                | `LiteDB`, `Serilog` suite     | Асинхронные очереди, фоновые `Task`, `CancellationToken`   |

## 🟦 Фаза 0: Фундамент, DI и инфраструктура потоков
**Цель:** Подготовить проект, настроить DI вручную, создать потокобезопасные очереди, заложить фиксированный шаг.

1. Инициализировать MonoGame проект. Добавить все пакеты из `DevKit.txt`.
2. Настроить **ручной DI** (`ServiceCollection`):
   - Зарегистрировать `DefaultObjectPoolProvider`, `ILogger` (Serilog), фабрики `Stateless`.
   - Собрать `ServiceProvider` в `Game1.Initialize()`.
3. Настроить **Serilog**: `Async` sink + `File` + `Thread` enricher. Проверить запись логов из разных потоков без блокировок.
4. Создать `GameThreadManager`:
   - Управлять `CancellationTokenSource` для `LogicThread` и `PhysicsThread`.
   - Реализовать `Start()`, `Stop()`, `Join(timeout)`.
5. Создать `ChannelHub` (используем встроенный `System.Threading.Channels`):
   - `_logicToMain` (позиции, состояния, команды спавна/удаления)
   - `_physicsToMain` (трансформы тел, коллизии)
   - `_mainToLogic` (ввод игрока, события UI, переходы)
6. Реализовать `FixedTimestepScheduler` в `Game1`:
   - Аккумулятор времени, цикл `while (accumulator >= FixedStep)`.
   - Отделить логику от рендера. `Draw()` работает на макс FPS, `Update()` привязан к 60 Гц.
7. Написать базовые `xunit` тесты:
   - Точность `FixedTimestep` (±1ms).
   - Потокобезопасность `ChannelHub` (чтение/запись из 2+ потоков).
   - Корректность DI и `ObjectPool`.

📦 *Пакеты:* DI, ObjectPool, Serilog suite, xunit  
🧵 *Потоки:* Main (инит), Logic/Physics (спящие, но созданные)

## 🟩 Фаза 1: Базовый геймплей (1 комната + цикл)
**Цель:** Реализовать перемещение, карту, врагов, бой, UI. Логика пишется в чистом виде, данные передаются через `ChannelHub`.

1. Настроить `MonoGame.Extended.Tiled`:
   - Парсинг `.tmx`, загрузка слоёв коллизий, маркеров спавна, декора.
   - Рендер через `TiledMapRenderer` в `Draw()`.
2. Подключить `MonoGame.Extended.Input`:
   - Абстракция `IPlayerInput` → маппинг клавиатуры/геймпада.
   - Передача ввода в `_mainToLogic` каждый кадр.
3. Игрок:
   - Сущность с позицией, скоростью, хитбоксом.
   - Управление через ввод из очереди. Анимация через `MonoSkelly` (обновляется в Main Thread по состоянию).
4. `Aether.Physics2D` (подготовка):
   - Создание `World`, добавление статических тел из Tiled-слоя стен.
   - Динамическое тело игрока.
5. Враги:
   - Спавн по маркерам. Машина состояний `Stateless`: `Idle → Detect → Chase → Attack → Die`.
   - Хитбоксы, параметры HP, урона, скорости.
6. Боевая система:
   - Ближний/дальний бой, кулдауны, отбрасывание.
   - Все снаряды/эффекты из `ObjectPool`. Ноль `new` в `Update`.
7. Условие очистки комнаты:
   - Счётчик живых врагов → при `0` отправка `RoomClearedCommand` в очередь.
8. UI (`Myra`):
   - HP, патроны/энергия, счётчик врагов, отладочная панель (FPS, нагрузка потоков).
   - Привязка к данным из Main Thread.

📦 *Пакеты:* Extended (Tiled, Input), Aether.Physics2D, Stateless, MonoSkelly, ObjectPool, Myra  
🧵 *Потоки:* Логика временно выполняется в Main Thread для скорости прототипа, но **все данные передаются через `ChannelHub`**. Готово к распараллеливанию.

## 🟨 Фаза 2: Активация многопоточности и детерминизм
**Цель:** Перенести тяжёлую логику в фоновые потоки, синхронизировать без блокировок, обеспечить детерминизм.

1. **Physics Thread:**
   - Перенести `world.Step(FixedStep)` в выделенный поток.
   - После шага читать позиции/скорости тел → писать в `_physicsToMain`.
   - Main Thread применяет координаты к визуальным сущностям.
2. **Logic Thread:**
   - Перенести `Stateless` AI, расчёт урона, спавн, кулдауны.
   - При >20 врагов использовать `Parallel.ForEach(chunks)` внутри потока.
   - Результаты (состояния, команды атаки, смерть) → `_logicToMain`.
3. **Main Thread Consumer:**
   - В начале `Update()`: `while (_channel.Reader.TryRead(out var cmd)) cmd.Apply();`
   - Никаких `lock`, `Task.Wait()`, `await` в игровом цикле.
4. **Детерминированный рандом:**
   - Заменить `System.Random` на `Xoshiro256**` или `System.Random(seed)`, передаваемый в Logic Thread.
   - Одинаковый ввод → одинаковый результат на любой машине.
5. **MonoSkelly интеграция:**
   - Анимации обновляются в Main Thread. Состояния из логики (`IsAttacking`, `IsMoving`) → вызов `anim.Play()`.
6. **Профилирование (`BenchmarkDotNet`):**
   - Замер времени шага Logic/Physics. Цель: `< 3ms` суммарно.
   - Оптимизация `Channel` пропускной способности, пулов, коллизий.
7. **Интеграционные тесты:**
   - Симуляция 300 тиков с фиксированным seed → проверка идентичности хешей состояний.

📦 *Пакеты:* Stateless, Aether.Physics2D, MonoSkelly, ObjectPool, BenchmarkDotNet  
🧵 *Потоки:* Полная многопоточность. Main = рендер/UI. Logic/Physics = фиксированный шаг. Синхронизация через очереди.

## 🟧 Фаза 3: Управление комнатами и переходы
**Цель:** Реализовать загрузку/выгрузку комнат, плавные переходы, управление состоянием игры, сохранение.

1. `RoomManager`:
   - Загрузка `.tmx`, парсинг коллизий, маркеров.
   - Сброс `Aether.World`, очистка пулов, пересоздание сущностей.
2. Порталы/двери:
   - Триггер → `_mainToLogic.Write(new TransitionRoomCommand { NextRoomId })`.
   - Логика останавливает AI, готовит загрузку.
3. Асинхронная подготовка:
   - Пока игрок в текущей комнате, Data Thread подгружает ассеты следующей комнаты в фоне.
4. Глобальная машина состояний (`Stateless`):
   - `Exploring → Transitioning → Cleared → BossFight → Victory`.
   - Безопасные переходы только между кадрами.
5. Управление памятью:
   - Возврат всех объектов в `ObjectPool` при выходе из комнаты.
   - Очистка `ConcurrentDictionary` кешей.
6. `LiteDB` сохранение:
   - Прогресс, статы, разблокировки.
   - Асинхронная очередь записи. Чтение при старте/загрузке комнаты.
7. Стресс-тест переходов:
   - 10 быстрых переходов подряд → проверка на утечки памяти, зависания потоков, потерю состояний.

📦 *Пакеты:* Extended.Tiled, Stateless, ObjectPool, LiteDB, Serilog  
🧵 *Потоки:* Room loading в Data/Logic Thread. Main Thread только переключает ссылки на безопасном кадре.

## 🟥 Фаза 4: Подготовка к Local Multiplayer
**Цель:** Поддержка 2-4 игроков, мультикамера, общий мир, подготовка к кооперативу без рефакторинга.

1. `PlayerEntity[]` вместо одиночного игрока:
   - Каждый игрок привязан к `IPlayerInput` (PlayerIndex 1-4).
   - Независимые статы, общие пули/враги/физика.
2. `Extended.Input` мульти-геймпад:
   - Чтение `GamePad.GetState(PlayerIndex.One/Two/...)`.
   - Fallback: WASD+Мышь (P1) + IJKL+Num (P2).
3. Камеры:
   - `Extended.Cameras.OrthographicCamera`.
   - Режимы: `Follow` (один игрок), `DynamicBounds` (все игроки в кадре), `SplitScreen` (2 Viewports).
4. Синхронизация мира:
   - Один `PhysicsWorld` на всех.
   - Враги/препятствия общие. Действия игроков маршрутизируются через `_mainToLogic`.
5. Кооп-механики (заглушки):
   - Friendly Fire toggle, revival, shared room clear counter.
6. UI адаптация (`Myra`):
   - HUD масштабируется под кол-во игроков. Панель HP/P1, HP/P2...
7. Финальная оптимизация:
   - Цель: 60 FPS при 4 игроках + 30 врагах + частицы.
   - Батчинг `SpriteBatch`, отсечение невидимых спрайтов, лимит глубины очередей.

📦 *Пакеты:* Extended (Input, Cameras), Myra, Aether.Physics2D, Stateless, ObjectPool  
🧵 *Потоки:* Архитектура не меняется. Логика уже общая. Main Thread рендерит несколько камер/вводов.

## 📜 Золотые правила многопоточности для этого проекта
1. **Никогда не вызывай `GraphicsDevice`, `SpriteBatch`, `Myra`, `MonoSkelly` из Logic/Physics/Data потоков.**
2. **Физика (`Aether.Physics2D`) работает строго в ОДНОМ выделенном потоке.** Не распараллеливай `world.Step()`.
3. **Main Thread только читает очереди.** Запись в `Channel` → из других потоков. Применение данных → строго в начале `Update()`.
4. **Используй `ObjectPool` для всего, что создаётся/удаляется чаще 1 раза в секунду.**
5. **Фиксированный шаг логики = детерминизм.** Без него Local MP и реплеи будут рассинхронизированы.
6. **`CancellationToken` обязателен.** При `Game.Exit()` все потоки должны корректно завершаться за <100ms.
